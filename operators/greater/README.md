## 题目与版本

两个输入按广播规则执行逐元素 `x > y`，输出 bool。不同 dtype、广播方向和连续性选择不同路径。

现有材料可以解释 **P33 的精确 INT32 紧凑路径**与 **P46 的 BF16 原始数据广播调整**。P33 / P46 的历史完整五例分别为 489.34 / 488.829 μs，但来自不同批次，不能由这两个数判断稳定优劣。最终 482.57 μs 上榜包尚待确认，因此这里称为代表方案。

## 精确 INT32 比较

保留输入为 INT32，通过以下恒等式把有序比较转为等值比较：

```text
x > y ⇔ !(min(x,y) == x)
x > y ⇔ !(max(x,y) == y)
```

共享输入在左时使用 Min，在右时使用 Max；两种方向都可以覆盖 dense 输入缓冲，并保留 packed 共享输入用于 EQ。比较位图表示 `x <= y`，再经 Select 反向编码为 0/1，转换为字节输出。

FP32 不能精确区分所有相邻 INT32，`x-y` 也可能溢出。这里的 half 仅用于已经得到的 0/1 结果编码，不把原始整数降精度后再比较。

## P33：比较完成后复用存储

P33 缩小常量向量，并在 packed 的最后一次比较读取结束后复用该区域保存 half 结果。腾出的 UB 允许 tile 从 8192 扩至 10240 个元素；目标配置显式分配 187904 B，加 8192 B 预留共 196096 B。

同场 C2 夹测为 F04 277.7455 → P33 273.095 → F04 277.476 μs，比两端均值少 4.51575 μs。已有 28 项定向 row 检查和完整五例严格正确性结果，覆盖广播双方向、极值、尾部及回退路径。

## P46：BF16 原始数据广播

P46 在已有紧凑版本上调整 BF16 重复行路径：先在原始 16 位数据布局上准备共享输入的广播，再进行比较所需的转换，减少扩大到 FP32 后的广播存储与处理。它沿用既有精确路径，不把输入降到 FP16 近似比较。

收尾完整五例为 `1.54 / 275.8255 / 31.3005 / 53.531 / 126.632 μs`，合计 488.829 μs。原始记录、完整五例及 ZIP/source/run 身份均有历史审计；这一结果仍属于本地设备实验。

更宽 tile、异步广播与双输出并不自动更快。一次 Gather 扩容还触发过内部 repeat 次数缩窄，必须先修正完整输出，再评价性能。
