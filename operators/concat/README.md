## P07 的四条新增或替换路径

P07 将小面板、连续输出命令、带预取的行段命令和直接 UB 分组路径合成一个默认包。Host 根据输入数量、布局、片段长度和容量选择分支，并保留已有基础回退。

| 路径 | 搬运组织 | 主要取舍 |
|---|---|---|
| 小面板，key 7 | Host 生成映射，把小输入面板连续读入，再完成局部重排 | 减少小输入的运行时调度；受输入数量与行宽条件限制 |
| 扁平输出命令，key 8 | 根据每核负责的输出区间建立连续命令，跨输入预取下一段 | 连续拼接不必走通用行间映射；需检查命令容量与尾部 |
| 行段命令预取，key 9 | 按实际行/输入片段建表并均衡分配；当前块出队后，先提交下一次连续读取，再写当前输出 | 尝试重叠 MTE2 与 MTE3，同时保留精确地址范围 |
| 直接 UB 分组，key 6 | 每路连续读取最多 16 行，在 UB 中 Gather 后做带行距输出，无额外 GM workspace | 减少临时区读写；单输入和单输出缓冲牺牲部分重叠空间 |

直接 UB 路径的配置记录为输入 65280 B、map 65536 B、输出 65536 B，共 **196352 B**。它仍然使用 Gather，不属于纯 MTE 方案。Host 在此合成包中把 workspace 大小设为 0；P06 的 GM 中转设计只能作为历史对照，不能套到 P07 上。

## 历史对照：P06 的分组中转

按拼接轴把连续输入理解为外层行数 H 和每路行宽 bⱼ。连续、较宽的片段适合直接搬运；大量窄输入则需要考虑将它们分组，降低碎片输出的成本。

分组路径先连续读取某路输入的一批行，打包到每核独立的 GM workspace；再从临时布局读回，通过 UB 中的 Gather map 将同一行的多路输入排在一起，按输出行步长写回。

```text
多路输入 → 连续 Pack → 每核 workspace
                       ↓
输出 ← 宽片段写回 ← Gather 重排
```

忽略填充时，这条路径请求约 4D 的 GM 读写，直接复制约为 2D。增加临时读写的动机是改善访问形态；workspace 的缓存命中并不由容量公式保证。

分组宽度、每 tile 行数、输入输出双缓冲和索引表共同竞争 UB。关键不是单独把 tile 做大，而是让布局、分核与预取可以同时工作。

P06 历史官方五例全部 Pass，总耗时 **323.30 μs**。后续同场 ABBA 中 P06 为 331.055 / 325.9165 μs，P07 为 312.2255 / 307.2455 μs；这些是另一轮本地测量，与上面的 307.1855 μs 分别保留。

## 保留下来的取舍与验证范围

- 后续候选复用索引初始化临时区，把数据槽从 32 KiB 扩为 38 KiB；目标输出 tile 数减少 20%，完整同场对照却没有形成足够稳定的收益，未替换 P06。
- 只保留一个输入槽能扩大组宽，但削弱了下一块输入的预取，历史完整耗时反而上升。
- 纯 MTE 路线减少了向量重排，Case5 仍明显慢于分组基线；不能由“少一条 Gather”直接推出整体更快。
- P07 在后续形状 `[1031,8022,2]`、126 路 float16 输入的额外边界检查中失败，根因未定位。五例性能结果和这项回归失败同时保留；“当前最好候选”不表示所有输入都已验证通过。
